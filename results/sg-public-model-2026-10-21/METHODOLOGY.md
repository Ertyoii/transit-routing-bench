# Singapore public-model routing benchmark methodology

Status: validation and the predeclared sealed test are complete; independent evidence acceptance passed on 2026-10-21. Publication review remains separate. No convergence claim is made.

## Claim and data tier

This is an explicitly public-modeled, finite static stop-pair benchmark. It is not an authoritative current Singapore service feed, observed rider-demand study, physical walking/accessibility verification, live LTA API test, production service or universal optimum. Dataset replacement is supported by the harness, but answer quality, supported semantics, preprocessing cost, frontier size and latency depend on the actual dataset, query distribution, hard caps and resources.

The transit source is the community Vorld/singapore-gtfs release v2026-07-12, acquired 2026-10-20. Its weekday frequency entries are deterministically expanded with phase-zero assumptions, not treated as individually observed departures. The evaluated service date is 2026-10-20, Asia/Singapore. Morning 07–10, midday 12–15, evening 17–20 and overnight 23–26 remain separate; times beyond 24 h are preserved. Unsupported weekend coverage is not scored as perfect empty transit service.

The primary conservative600 snapshots have 5,450 model stops and 40,230 directed footpaths: 70 inherited proxies and 40,160 conservative OSM-derived entries. The OSM regional extract is dated 2026-10-19. 3,632 anchors are conservatively bound; 1,818 unbound anchors and unverified connector/access assumptions remain limitations. Both bus and rail are present in the transit model; this is not complete current bus/rail coverage. Hypothetical rail-entry/exit sensitivity is a separate data variant and must not be pooled with the primary tier.

Retain raw/normalized hashes, source URLs, acquisition times, assumptions and normalization/build helpers. Do not redistribute source databases, LTA map assets or full derived databases without a separate rights review. Public availability alone is not a redistribution license. OSM attribution and ODbL obligations remain applicable. No API credential is needed for these retained public-model experiments; no credential is published.

## Workload and hard limits

Endpoints, departures, labels and split IDs were committed from metadata before routing outcomes. Primary requests have one origin stop and one destination stop, a 3,600 s arrival horizon, at most 4 boardings, 600 s each access/egress/transfer/direct walking block, 3,000 s aggregate walking and zero added transfer buffer. The 3,000 s total is nonbinding at these primary block/boarding limits; a 2,400 s challenge is separately named. Display k3/k5 is not the same parameter as native candidate k10.

Four windows share OD clusters and must not be treated as independent population samples. Screen panels have 180 tune / 90 validation / 90 test requests per window; full panels have 900 / 450 / 450, split across 300 / 150 / 150 unordered parent-station OD clusters and three departure offsets. The 12-request tune smoke is functional coverage only. The strict-CSA validation/test cohort uses every frozen screen request (90 per window), with matching point-router quality anchors, separately labeled from the primary 450-request full panels. It is not equally qualified merely because its smoke completed. Model-empty, hard, unsupported, timed-out and preparation-unavailable cases are retained; no easy-query resampling or silent denominator intersection is permitted. An endpoint-only preflight checked both exact directed-stop pairs and canonical unordered parent-station pairs, including reversals, across smoke tune, screen tune, full validation, screen validation, full test and screen test. All panels are pairwise disjoint at both units. This does not establish geographic/corridor or population independence.

Validation outcomes are exposed only after their declared validation release; test outcomes remain untouched until the separately sealed final release. Final test requires source/configuration freeze, accepted public-model input qualification and an exact mode-specific seal. An exposed test cannot be made untouched by rehashing it. Official/latest-data qualification is a different, unchanged tier and cannot be inferred from the public-model seal.

## Native contracts, not one misleading league table

- RAPTOR/EA-CSA/capped ULTRA represent arrival-versus-boardings 2D frontiers under the primary hard caps.
- McRAPTOR additionally retains walking as a 3D Pareto objective. More work and more preference coverage are not interchangeable with a 2D speedup.
- Strict CSA arrival variants return identity top-k from one lane. Score variants run separate boarding-cap lanes 0 through 4, validate/rank their union (up to five k-sized lists, not necessarily only ten raw/final identities), and certify the ranked score result. The one-million-label ceiling is per lane, so score work/resources are not the same as arrival work. These are different contracts from Pareto representatives or display diversity. Shared-scan batch 1 demonstrates compatibility, not a batching advantage.
- Trip-Based/FLASH/TP/TREX variants retain their declared static-rule, fixed-cap, source/destination-domain, walking-metric and preprocessing contracts. Unsupported requests remain visible. Resource exhaustion is not mathematical infeasibility.
- ProfileCSA/rangeRAPTOR consume exact registered point bytes but derive the inclusive 61-readiness interval [departure, departure+60], keeping latest arrival fixed. Whole-window latency is not divided by 61. Every materialized grid witness and the boarding-cap arrival-vector grid are checked.
- Native TAD returns one earliest-arrival witness. Projection of richer EA/RAPTOR references checks minimum-arrival agreement, not equal-work performance.
- Canonical native ULTRA rejects the supplied nonempty GTFS transfer-rule table. Rules are not removed to manufacture acceptance. This is separate from the implemented capped control/safe-subset adapters.
- CoreCH is transfer-footpath-graph-only one-to-many shortest-path rows, not full transit routing. Scalar 600 s graph distance is not the collection of endpoint-role/aggregate/accessibility/transit restrictions. All original positive directed footpaths are used, including model proxies. Query OD endpoints protect anchors during preprocessing; a whole row includes all requested targets and is never divided into invented per-target latency. Independent bounded Bellman-Ford raw-edge reference work is preparation, not query time. The initial 24-anchor smoke has only self-reachable cells and cannot support a nontrivial route-performance claim. An additional frozen screen panel has 117 anchors, 117 whole rows and 13,689 cells per method/window, retaining all 105 self-only rows alongside 12 rows with positive nonself reachability; no CoreCH speedup was demonstrated.
- OpenTripPlanner is absent from this Go inventory. No substitute is relabeled OTP and no external-system parity is asserted.

## Timing and resources

Core familybench experiments isolate one router/configuration per fresh process. Linux amd64, recorded AMD EPYC 9V74, Go 1.27.3; nine visible logical CPUs, affinity CPU 0–3 and GOMAXPROCS=4. Affinity is not dedicated-core isolation. GOMEMLIMIT=7 GiB is a soft GC target, not a hard RSS/cgroup cap. Native 7.0 GB sampled RSS protection and an outer monitor are development safeguards that can miss transients; decimal GB and binary GiB differ.

Per-request response starts at common in-process submission and includes queueing, search, reconstruction, validation, ranking and enabled quality/selection. It excludes file parsing, router/checker/quality-index preparation and JSON artifact/transport serialization. Startup components, process wall, first-offered response, allocation deltas and whole-process sampled RSS are separately reported. Prelaunch hashing reads files and can warm OS pages: fresh process does not mean cold disk, globally flushed cache or a measured production first-byte response.

Each fresh process executes an entire offered workload, not a new process for each request. Only its first offered request is the first query after construction. Witness/result records are retained for later artifact output, so their memory and GC effects can influence later requests even though artifact serialization is outside the response clock. This is not isolated per-request process-cold latency.

Primary repeated blocks retain one measured 180-query pass per fresh process with zero discarded warmups. A second block reverses window/variant ordering. Forced deadlines and any retained warmups remain labeled and excluded from ordinary measured quantiles. Auxiliary native drivers run multiple native controls in one process and share preparation; their cumulative RSS is not isolated per algorithm and their timings do not join the core point-frontier league table.

Every offered outcome is counted. Failure/unsupported/not-run/unresolved rows have no invented successful latency. Successful- or transit-conditioned quantiles are explicitly labeled; overall attempted response and failure coverage accompany them. p50/p95/p99 use empirical nearest ranks, not production/population tails. OD-cluster resampling retains recorded within-cluster departures and repeated blocks and is conditional on those processes; it does not estimate host/process-noise or rider-population confidence. Process-to-process variation remains visible.

## Quality and selection

An independent Python implementation reconstructs finite-model journey feasibility from original connections/footpaths/transfer rules, not router imports. Feasible common-pool witnesses can falsify declared arrival/boarding-cap or frontier certificates. Agreement and no counterexample do not create an independent full-network completeness proof. Strict identity top-k reconstruction is not implemented in the large-model evaluator. Separate tiny exhaustive/specification oracles and frozen-baseline differential/race/ownership/cancellation tests qualify source changes within their tested scopes.

The observed union witness pool is explicitly incomplete and changes with contributors; compare only exact common pool/config bindings. Quality separates raw discovery, validated candidate retention and displayed k3/k5 selection. All offered failures remain in coverage; model-empty cases retain outcome denominators but have no finite preference optimum.

The 20 declared score hypotheses are elapsed time plus transfer_seconds×transfers plus extra_walk_weight×walking_seconds, with transfer weights 0/150/300/600/900 and extra walking weights 0/1/2/4. Walking is already part of elapsed time. These are not learned/authenticated rider preferences or population probabilities. Regret is measured in score-seconds, not necessarily realized travel-time seconds.

Default display uses a fixed 300 s transfer penalty. The separate existing finite_preferences_v2 selector is optimized to the SAME 20 hypothetical evaluation weights, not a heldout preference model. Its max_subsets=200000 and max_candidates=1024 guards are explicit and selection/deadline failures remain failures. The measured implementation computes k3+k5 minimax and anchor controls together; its total quality phase is not top-3-only cost. Default and finite outputs are independently reconstructed from the same output files and exact same witness pools.

## Optimization and reproducibility

Retain baseline and all rejected/prelaunch/malformed/resource-limited attempts. Corrected retries use fresh directories and do not overwrite failures. Source changes must preserve hardcaps, feasibility, native contracts, tie witnesses, ownership/cancellation and certificates; differential tests alone are not a full-network proof. Source/build/vendor/binary hashes, complete patches including new files and command/input identities accompany results. No race/profiling binary is used for headline latency. Whole-run profiles include loading/checking/ranking and are diagnostic, not clean query-only attribution.

Measure structural variants and explicit resource tiers separately, including added allocation/RSS/preparation. Faster decline is not speedup; more completion from a larger label ceiling is a resource-quality tradeoff. Batching keeps complete submission deadlines and never divides batch/row makespan into individual latency.

The bounded source-candidate search tested the following distinct hypotheses, each first qualified against frozen native outputs and independent small-instance oracles where available:

- Strict CSA builds relaxed reverse latest-readiness bounds by remaining boarding count, with an in-vehicle continuation bound, then rejects provably dead-end labels/transitions before materialization. This is necessary-condition feasibility pruning, not a claim that it merely skips earlier connections. Native identity-top-k ordering is preserved; shared-scan batching remains a separate experiment. Its original low-label-budget failures are not retroactively replaced by larger-budget successes.
- Query walking uses immutable dense graph ordinals, query-local reusable scratch and typed heap storage, while retaining exact cap boundaries, native tie order, witness ownership and cancellation. It trades retained scratch/index storage for fewer transient allocations.
- EA-CSA uses immutable dense trip/stop/connection ordinals, lazily allocated per-query layers and closure caching. The combined walking-plus-EA candidate is actually measured; independent gains are not multiplied into an invented combined result.
- RAPTOR caches query-local dense readiness/path ordinals and preindexes alighting stops while preserving native iteration, rule checks, pruning and cancellation polls. Added query metadata is counted in allocations. Ordinary and Early entrypoints remain distinct.
- Capped ULTRA uses dense query-label/readiness structures under the same cap-safe control/subset certificates. Better response does not imply lower allocation or a canonical unrestricted ULTRA speedup.
- Fixed-cap Trip-Based/TP/TREX walking preparation uses a proved role-cap-bounded closure without silently substituting a truncated metric for an unrestricted contract. Larger retained-transfer ceilings are explicit operating points, with preparation time, actual retained-link counts and RSS reported. Full-metric FLASH/TREX preparation limits remain unavailable rather than being relabeled a new bounded variant.

Whole-run diagnostic profiles motivated these hypotheses but are not clean query-only attribution or headline timing evidence. The ledger records unsuccessful ideas, guards, source identities and remaining search space. A variant selected on tune/validation was frozen before any corresponding test routing outcome; test observations cannot justify a new source, budget, selector or query cohort in this release.

Convergence is not presumed. The declared finite protocol requires covered/excluded search space, two equal-budget rounds without a new ≥3% validation-p95 Pareto improvement, two clean repeated blocks and a fresh sealed holdout. Finite search exhaustion would still not prove a theoretical global optimum. If these criteria remain unmet, publish best measured bounded configurations and explicitly list unexhausted/pending families, not “optimized to the absolute limit.”

Published portable projections replace execution-local paths and therefore differ in byte hashes from preserved originals; retain original hash references. Rebuilding on a new machine requires new environment bindings and any new final-evaluation seal. No claim of identical cross-hardware timings follows from reproducible code/data hashes.
